# 维护与验收要求

用户功能、技术契约、运行配置与测试均须以当前源码为准。历史过程记录不作为交付资料，文档不声明未经独立验证的性能、恢复或安全结果。

1. 新端点/字段先登记契约，再实现，已有字段、单位及权限语义保持兼容。
2. 页面操作必须对实际 API 生效；无接口支撑的控件禁用或移除，并写明功能边界。
3. 认证、科室范围、强制脱敏、告警/工单事务及失败回滚使用独立样本检查。
4. 非空数据库恢复后核对表内容、结构、序列和关键 API；接收方负责启用备份、告警及进程恢复。
5. 测试结论区分通过、失败和未验证，不把历史记录或源码能力当成目标部署结果。

当前边界见 [实现清单](current-state.md)，后续要求见 [工程验收计划](engineering-acceptance.md)，运行方式见 [README](../README.md)。
