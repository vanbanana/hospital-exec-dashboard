# 合成数据供给方案 — EDSS（v2.2）

> 无法取得真实医院数据是固定约束；合成数据的可复现性、契约正确性和统计自洽仍属于 [工程验收](engineering-acceptance.md)。

## 0. 数据供给

运行时没有 src/mock 或组件内编造的业务数据。取数路径：

```text
固定种子 SQL → PostgreSQL 明细/汇总/集市 + sim.clock
                    ↓ Go handler → repo → 契约 JSON
                    ↓ client.ts → API 函数/共享 composable → 页面
```

后端开启 sim 时 40 个方法/路径组合，关闭时 35 个；60 张业务表，见 [当前清单](current-state.md)。会话、偏好、日期使用共享 Vue 模块；不要求 Pinia 或 Redis。数据库读写及前端调用真实执行，业务来源明确标示 demo。

## 1. 种子与样本纪律

1. 字段名、金额/率值单位、null 和枚举对齐 api-contract.md；前端不在失败后编造业务值。单元测试允许替身。
2. 固定种子版本、业务日期与输入，以稳定主键派生数据；业务锚点为 2026-10-28 09:00+08:00，不等于当前自然日期。
3. 同指标跨页面只有在时间窗口、过滤和口径相同下才应同值。分项合计、费用单位、分母及环比方向需独立样本断言；合理量级的 ±10% 不能替代精确勾稽。
4. 种子可用骨科 DRG 亏损、急诊留观超时等场景解释业务；场景成立与数据量级只是演示依据，不代表医院真实业务有效性。
5. 测试样本覆盖零行、null、零分母、日期边界、跨科室、重复提交与并发竞争；不需要医院资料。

## 2. 可执行演示剧本（当前后端轨）

1. 首页查看合成全院指标、风险事件。
2. 专题 DRG/医疗/运营页查看相关汇总和明细；当前无五级病例穿透，不描述为逐例下钻闭环。
3. 告警认领/派发 → 工单接单/办结，验证告警、工单与审计的状态变化。
4. 办结只改变业务状态，不自动让指标复常。演示指标恢复须准备独立合成场景或实现派生逻辑，不能暗示现役流水线已重算。

## 3. 仿真控制面档 A（已实现）

全部五个 /sim/* 端点限 admin 会话，操作见 [sim-runbook.md](sim-runbook.md)：

- GET/POST /sim/clock：读取/设置业务时钟。
- POST /sim/tick：单次前移不超过 43200 分钟；上界 seed_end+1 天，越界 35002；重复提交会重复推进，不幂等。
- POST /sim/reset：复位 base_date 09:00，时钟复位幂等；scope=full 未开放，返回 35002。
- GET /sim/jobs：操作台账分页。

SIM_ENABLED=0 不注册这些路由；合法会话请求走 NoRoute 10003，无会话可能先返回 20001。production 覆盖强制关闭控制面，sim.clock 表与业务时钟继续保留。

tick 只推进时钟，不生成事实或重算集市。同日推进按已有查询语义读取；跨日工作台读取种子窗口内数据，ads 快照保持最近派生切面。种子窗至 2026-12-31，seed_end 缺省取 MAX(dwd.charge_day.date)。这不证明所有跨日指标自洽，相关异常与窗口边界需按工程计划验收。

## 4. 未实施与范围决策

常驻 Fact/Derived、DayGen/Intraday 生成、AlertScan、scope=full 重播种和自动 runner 均未实施。先确定所需合成场景与契约，再按需实现；没有实时医院接入前置条件。工程验收可先用确定性 SQL/隔离样本验证，无须先建立复杂生成平台。
