## 未通过及修复过程

- 原查询的短测未达延迟门槛；增加同事务维护的门诊日汇总与收费日/科室汇总后，重新完成整段 30 分钟测试。中途停止的 741 秒记录保留，不充当完整通过。
- 并行镜像构建曾占满云盘。清理本任务缓存和冻结的临时 SDK 容器，保留数据库/有效备份；新增串行构建和每目标 6GiB 空间门槛，状态文件不可写时调度继续运行。门槛是预检，不保证构建永不耗尽空间。
- 新 SQL 文件宿主权限曾导致生产非 root 容器无法读取。Dockerfile 显式赋予只读/目录访问权限，重建后运行非 root 文件检查、升级与 HTTPS 检查通过。
- 完整负载期间，开发测试的 Compose 启动因日志配置变化重建 DB，造成 83 次业务失败，并中断全新初始化及首次连接池演练。修复开发脚本以复用运行中的健康 DB；再次实库 race 检查通过，DB 容器 ID/创建时间未变化。最终负载含此干扰仍满足固定门槛，但不能称为零错误或无中断。
- 全新库的 18 个迁移和前五个种子通过，第六个种子因上述 DB 重建回滚；按规范文件恢复后续八个种子后，全部13文件覆盖完成；新库独立汇总断言、18迁移重跑（applied0/skipped18）、ready200和五个认证业务API均通过。不能描述为一次无中断冷启动。

原始私有归档、恢复摘要、故障日志及未完成测试日志留在被忽略的 backups/、/tmp。公开摘要只保留计数与结果，不包含业务行、DSN、Cookie、会话令牌或密钥。
