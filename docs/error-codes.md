# 统一响应包络与错误码规范 — EDSS

> 版本：v1.2（v1.1 契约冻结基线存续——**只追加不改号**；v2.0 增补注册见附录 A，P3 批落地的新码已并入各段注册表）
> 实现对齐：真实医院数据不纳入验收，工程标准见 [工程计划](engineering-acceptance.md)。
> 状态：包络规范已生效——Go 后端 `envelope` 包统一出口，前端 `client.ts`（原生 fetch）拆解；前端无 mock 轨，包络即唯一响应形状。
> 冻结契约。任何端点必须返回本包络；前端 client.ts 负责包络拆解与认证重定向；页面/composable 负责面板、表单与 toast 展示（§4）。

## 1. 响应包络（Envelope）

**成功**（HTTP 200）：
```json
{ "code": 0, "message": "ok", "data": { }, "trace_id": "a1b2c3d4e5f6", "ts": 1758153000 }
```

**失败**（HTTP 状态按 §3 映射，包络不变）：
```json
{ "code": 20101, "message": "用户名或密码错误", "data": null, "trace_id": "a1b2c3d4e5f6", "ts": 1758153000 }
```

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| code | int | 业务码。`0`=成功；非 0 见 §3 注册表 |
| message | string | 人类可读（中文）。前端默认直接展示，也可按 code 覆盖文案 |
| data | any / null | 成功负载；失败时可为 null 或含 `fields` 校验明细 |
| trace_id | string | 每请求唯一（middleware 生成），日志排障用；前端报错时随用户反馈上送 |
| ts | int | 服务端 unix 秒 |

**分页负载约定**（data 内嵌）：
```json
{ "list": [...], "page": 1, "size": 20, "total": 137 }
```
查询参数统一 `?page=1&size=20`（size≤100）。

## 2. 错误码段位

| 段位 | 域 | HTTP 映射倾向 |
| :--- | :--- | :--- |
| 0 | 成功 | 200 |
| 1xxxx | 通用/参数/系统 | 400 / 429 / 500 |
| 2xxxx | 认证与权限 | 401 / 403 |
| 3xxxx | 业务（按模块分段，见下） | 200/400/404/409 |
| 4xxxx | 数据管道内部故障（ETL/聚合任务，对 API 表现为上游无数据） | 500/503 |
| 5xxxx | 外部依赖（预留：HIS/ES/MQ） | 502/503 |

业务段内部分配：`30xxx` 通用业务资源 · `31xxx` 大屏与指标 · `32xxx` 下钻与病例 · `33xxx` 告警与督办 · `34xxx` 字典与组织 · `35xxx` 仿真控制 · `36xxx~39xxx` 预留扩展域

**两条铁律**：
1. **HTTP 200 + 非 0 code 全系统仅 31004 一例**（指标口径正常但无数据）；新码评审禁止再引入此模式。**列表端点空集合一律 code=0+空 list**，不得用非 0 码表达"没数据"。
2. 4xxxx = 数据管道内部故障（ETL/聚合任务），35xxx = /sim 仿真控制 API 层错误，二者不重叠。

## 4. 前端统一处理矩阵（当前实现）

原生 fetch 客户端设置同源 Cookie 和 30 秒超时。它不直接弹全局消息，也不管理表单；错误对象交给 useAsyncData 或操作调用方。

| 条件 | 当前行为 |
| --- | --- |
| HTTP 200 且 code=0 | resolve(data) |
| code=31004 | 返回 data（契约为 null），页面渲染空态 |
| HTTP 401 或 code=20001/20002/20003 | 非 auth/* 请求清会话并硬跳 /login?redirect=当前路径；auth/* 由登录页/路由守卫处理 |
| code=20004/20005 | 抛错误；读取面板显示错误，写操作显示 toast/内联提示；无独立 /403 页 |
| code=20101/20102/20104 | 登录页显示服务端错误文案；没有锁定倒计时 |
| code=10001/10002 且 data.fields 存在 | Error.fields 透传调用方；表单按已有映射展示，不存在 FormError 类 |
| code=33002/33104 | Error 透传 current_status/todo_id；对应告警/工单调用方提示并按实际路径局部重取 |
| 其余非零 code | Error 透传 code/message/trace_id，由面板或操作 toast 展示 |
| 非 JSON 网关响应 | 抛 [api] http N；不存在上游 trace_id 时由前端错误归一产生本地标识 |
| HTTP 5xx、超时、网络断 | 工作台错误/重试或 stale；大屏首屏失败显示红条与手动重试，有旧快照时标 stale，后台每30秒轮询 |

未实现项：refresh 单例队列、统一按钮冷却、自动重连倒计时、统一错误上报服务。不要将历史目标写成已实现行为。登录失败锁定由 PG sys.audit_log 计数，没有 Redis；常规恢复等待十五分钟窗口，不通过删审计历史解锁。

**文案纪律**：默认显示 message；判断分支按 code，不按 message 字符串。错误码、HTTP 映射和契约语义保持原样；自研 WbToast/反馈原语负责页面呈现，不要求 Element Plus。

## 5. 校验错误负载（code=10002）

```json
{ "code": 10002, "message": "参数校验失败",
  "data": { "fields": { "deadline": "必须晚于当前时间", "assignee_id": "不能为空" } } }
```
客户端将 fields 挂到 Error 对象，已支持字段映射的表单消费它；未映射的表单显示 message。当前使用自研输入组件，没有 el-form-item；逐表单字段覆盖属于后续验收。
